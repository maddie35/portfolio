About

I write documentation, and teach the things documentation can't.

For the last decade, I've written everything from product documentation, API references, and release notes to admin guides, process docs, and style guides. I read code well enough to be useful, and I ask engineers and product managers direct questions without wasting their afternoon.

I test before I write, and then I test what I write.

Accessibility isn't a review step for me. Plain language, real headings, sensible reading order, and text that survives a screen reader make documentation better for everybody. And building it in from the start is cheaper than retrofitting it later.
